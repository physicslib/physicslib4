## Findings

### Medium

**F-1. Axiom 5's coherence-with-isotony clause carries two undocumented
well-formedness hypotheses, plus one fully redundant hypothesis, none of which
appear in the blueprint prose or the declaration's own docstring.**

- `haag-kastler-axioms-in-curved-spacetime.tex:93-126`
  (`def:isometric-covariance-in-curved-spacetime`, Axiom 5) states condition (3)
  as: "for Alexandrov topology basis elements `Bι ⊆ Bκ` and the unital
  `*`-monomorphism `i` of Axiom 2, `α_φ` commutes with `i`" — with no further
  qualification.
- `Physicslib4/AQFT/HaagKastlerCurved/IsometricCovariance.lean:94-102`:
  ```
  ∀ (φ : M.Isom) ⦃B₁ B₂ : Set M.Carrier⦄
    (hB₁ : M.IsBasisSet B₁) (hB₂ : M.IsBasisSet B₂)
    (h : B₁ ⊆ B₂)
    (hφB₁ : M.IsBasisSet (φ • B₁))
    (hφB₂ : M.IsBasisSet (φ • B₂))
    (hφ : (φ • B₁ : Set _) ⊆ φ • B₂)
    (a : U.algebra B₁),
      (α φ B₂ ...) (i.map hB₁ hB₂ h a) = i.map hφB₁ hφB₂ hφ ((α φ B₁ ...) a)
  ```
  carries three hypotheses (`hφB₁`, `hφB₂`, `hφ`) that are absent from both the
  blueprint prose and the declaration's own docstring
  (`IsometricCovariance.lean:55-77`, which restates condition (3) as "for every
  `φ` and inclusion `B₁ ⊆ B₂`, `α φ B₂ ∘ i.map = i.map ∘ α φ B₁`" with no
  mention of them).
- `hφB₁`/`hφB₂` are not cosmetic: `Isotony.map` (Axiom 2) is only defined given
  proofs that both endpoints are basis sets
  (`Isotony.lean:58-60`), so the right-hand side `i.map hφB₁ hφB₂ hφ` does not
  even typecheck without them. This is exactly the caveat the blueprint *does*
  disclose for the downstream theorem `thrm:von-neumann-geometric-covariance-in-curved-spacetime`
  (`tex:281`: "the abstract `LorentzianSpacetime` interface does not supply
  basis-set preservation ... so it enters as an explicit hypothesis") — but that
  disclosure is written only at the point the caveat resurfaces, not at Axiom 5
  itself, where it originates. Consequence: for any `LorentzianSpacetime`
  instance in which `IsBasisSet` is not preserved by some isometry `φ`, clause
  (3) of Axiom 5 is *vacuously* satisfied for that `φ`, `B₁`, `B₂` — a real
  restriction on what "isometric covariance" forces, on the abstract interface,
  that is not recorded anywhere per the project's `Restriction:` convention.
  (The trivial witness net, `trivialLocalNet_isometricCovariance`,
  `Net.lean:353-358`, happens to prove clause (3) genuinely rather than by this
  vacuity, so satisfiability is not itself in question — this is about what the
  axiom fails to force on *other* instances of the interface.)
- `hφ : (φ • B₁ : Set _) ⊆ φ • B₂` is, separately, fully redundant: it follows
  from `h : B₁ ⊆ B₂` alone via `Set.smul_set_mono h` (true for the image of any
  function, not just a group action), yet is threaded as an explicit hypothesis
  in the foundational Axiom 5 definition itself. This is the same pattern the
  2026-09-25 review flagged as Finding N-2 in `GeometricCovariance.lean`'s
  *derived corollaries* (since fixed there — the current `GeometricCovariance.lean`
  derives this inclusion internally via `smul_subset_of_mem_stabilizer` rather
  than asking for it); it has not been cleaned up at its original occurrence in
  `IsometricCovariance.lean`, which is the more consequential site since every
  downstream axiom-5 consumer inherits it.
- *Suggested fix (report only, per role)*: add a `**Restriction:**` docstring
  line to `IsometricCovariance` naming the basis-set-preservation gap and noting
  it is closed for concrete spacetimes by
  `toAbstractIdentityComponent_isBasisSet_smul` (`IdentityComponent.lean:103-110`);
  and/or drop the redundant `hφ` and derive it internally with one `have` (as
  `GeometricCovariance.lean` now does), the same fix already applied downstream.
