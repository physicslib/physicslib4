## Findings

### Medium (carried forward from `review-2026-09-26-sec10.4.md`, still unresolved) — `IsPastEndpoint`/`IsFutureEndpoint` are typed for `SmoothPath`, contradicting the blueprint's explicit "no smoothness input" clause

**Location:** `Physicslib4/Spacetime/Curves.lean:920,932`, cited by
`def:endpoints` (`spacetime.tex:270-281`).

Blueprint text (`spacetime.tex:278`, emphasis in original):

> "For an arbitrary path $\mu$, the past and future endpoints are singled out
> by extremality of the *parameter*, not by counting boundary components, and
> **no causal or smoothness input enters**: $p$ is a *past endpoint* of $\mu$
> if there is an $s \in \Sigma$ with $\mu(s) = p$ that is *minimal*..."

Lean (unchanged since the prior audit):

```lean
def IsPastEndpoint (μ : M.SmoothPath) (p : M.Carrier) : Prop :=
  ∃ s ∈ μ.parameterSpace, μ.toFun s = p ∧ (∀ s' ∈ μ.parameterSpace, s ≤ s')

def IsFutureEndpoint (μ : M.SmoothPath) (p : M.Carrier) : Prop :=
  ∃ s ∈ μ.parameterSpace, μ.toFun s = p ∧ (∀ s' ∈ μ.parameterSpace, s' ≤ s)
```

Both take `μ : M.SmoothPath`, not `μ : M.Path`, even though the definition
body uses only `parameterSpace`, `toFun` and the order on `ℝ` — exactly what
the blueprint's own body says, and nothing that needs smoothness. The
companion `IsEndpoint (μ : M.Path) (p : M.Carrier) : Prop` (`Curves.lean:905`)
is correctly stated for a general `Path`; it is the two more specific
predicates that narrow the domain. This is "Lean assumes more" — an extra
structural hypothesis (smoothness + non-vanishing derivative on the path) not
present in, and explicitly disclaimed by, the blueprint's own wording. No
downstream theorem currently needs the general-`Path` form (every consumer —
`IsTripSegment`, `IsCausalTripSegment`, the pushforward lemmas, the
Minkowski-specific corollaries — only ever applies it to a `SmoothPath`), so
it has no observed proof consequence, but as a standalone definition audited
against its cited blueprint entry it is narrower than stated, and — unlike
the `IsGeodesic` precedent — the narrowing carries no `**Restriction:**`
docstring line.

I independently re-read `Curves.lean` in full this session (not relying on
the prior memo) and confirm the code is unchanged at these lines; this
finding is real and still open, not something I am re-discovering
independently — crediting the 2026-09-26 audit for the original report.

### Low (carried forward, still unresolved) — no `Curve`/`SmoothCurve`-level endpoint predicate

`def:endpoints` says a point is an endpoint "of a path $\mu : \Sigma \to M$
**or its associated curve**" (`spacetime.tex:271`). Only the `Path`/`SmoothPath`
forms are formalized (`IsEndpoint`, `IsPastEndpoint`, `IsFutureEndpoint`);
there is no `Curve.IsEndpoint` or `SmoothCurve.IsPastEndpoint` defined via
`Quot.lift` or an existential-over-representative, the pattern used elsewhere
in this file (`IsTimelikeSmoothCurve`, `IsFutureOrientedSmoothCurve`, etc.).
Consistent with how the definition is consumed downstream (`IsTrip` always
goes through a representative `SmoothPath` directly), so nothing is blocked,
but the blueprint's "or its associated curve" clause has no Lean witness.
Re-confirmed present (still missing) this session.

### Low (carried forward, still unresolved) — asymmetric strictness between `PathEquiv` and `SmoothPathEquiv`/`OrientedSmoothPathEquiv`

`PathEquiv` (`Curves.lean:264`) requires a homeomorphism `φ : ℝ → ℝ` defined
(and inverted) on **all of `ℝ`** that happens to map `Σ₁` onto `Σ₂`.
`SmoothPathEquiv`/`OrientedSmoothPathEquiv` (`Curves.lean:279,297`) only
require `ContDiffOn`/mutual-inverse conditions **on the respective parameter
spaces**, with no requirement that `φ`, `ψ` extend to a diffeomorphism of all
of `ℝ`. Mathematically almost certainly harmless (any homeomorphism/
diffeomorphism between two non-degenerate closed intervals of `ℝ` extends to
one of all of `ℝ`), but the two Lean definitions sit at different levels of
generality without comment, while the blueprint's wording ("a homeomorphism
of the parameter space", `def:curves`) is uniform across both clauses.
Low severity, judged by reading only; re-confirmed present this session.
