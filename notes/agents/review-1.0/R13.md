# R13: cross-cutting review of the Lean library

- ID: R13
- Scope: the whole Lean library `Physicslib4/` (ignoring `scratch_*`): namespaces/naming,
  duplicated declarations/helpers (in-repo or vs. Mathlib), dead code (not used/cited by any
  blueprint `\lean{}`), module structure and imports, every `set_option` (especially
  `maxHeartbeats`, `backward.isDefEq.respectTransparency`), build warnings, module/declaration
  docstring coverage, blueprint label citations that don't exist, universe hygiene, bad `@[simp]`,
  `erw`/`convert` density, very long proofs, the `**Restriction:**` convention.
- Excluded (already reported by section reviewers, see brief for full list): erw in
  Spectral/Unbounded/DirectSum.lean (262,294,467); respectTransparency in Spacetime/Pullback.lean,
  CrossMetricIsometry.lean, StandardMinkowskiSpacetime; missing Restriction for oriented identity
  component in HaagKastlerCurved/Concrete.lean; `IsGroundStateForFlow` using `K : Type`;
  lmm1/lmm2/cauchy_schwarz_inequality unused by gns_construction; strongContinuous_of_weak;
  LorentzCausality.lean and orthochronous Lorentz section of Minkowski.lean lacking blueprint nodes.
- Method: scripted surveys (Python/grep, scratch output in /tmp only), then targeted reads.
- Date: 2026-10-10

  - Physicslib4/AQFT/HaagKastlerCurved/StabilizerKMS.lean:99
    `IsKMSStateForFlow.exists_gns_unitary_strongContinuous`, :148 `IsGroundStateForFlow` (a second,
    stabilizer-indexed definition of the same name as the one already flagged elsewhere), :172
    `IsGroundStateForFlow.exists_strongContinuous_unitary`
  - Physicslib4/AQFT/HaagKastlerCurved/StabilizerAction.lean:150 `exists_gns_unitary_stabilizer`,
    :185 `exists_gns_unitary_stabilizer_strongContinuous`, :212 `exists_gns_unitaryRep_stabilizer`,
    :235 `exists_gns_unitaryRep_stabilizer_strongContinuous`, :265
    `exists_gns_irreducible_covariant_stabilizer`
  - Physicslib4/AQFT/HaagKastler/VacuumState.lean:129 `HaagKastlerNet.IsVacuumState`
- protected: no (these are theorems/defs built on top of `gns_construction`, not axiom-structure
  fields, though `HaagKastlerNet.IsVacuumState` and `IsGroundStateForFlow` are Prop-valued
  definitions used as standing hypotheses elsewhere, so changing them is semi-protected)
- verdict: confirmed
- evidence: the underlying theorem these all build on is universe-polymorphic:
  `theorem gns_construction.{u} {A : Type u} [CStarAlgebra A] (ω : State A) : ∃ (H : Type u) ...`
  (Physicslib4/GNS/Construction.lean:64-65). Every declaration listed above instead asserts
  `∃ (H : Type) ...` or `∃ (K : Type) ...`, e.g.
  `theorem exists_isLocalObservable {U : LocalNet M} {B : Set M.Carrier} (ω : State (U.algebra B))
  {a : U.algebra B} (ha : IsSelfAdjoint a) : ∃ (H : Type) ... := by obtain ⟨H, hng, hip, hcs, π, ...⟩
  := gns_construction ω` (LocalAlgebra.lean:94-99) — the proof calls the universe-polymorphic
  `gns_construction` and then states a `Type 0`-only conclusion, discarding the generality the
  lemma it is built from already has.
- proposed fix: make `H`/`K` universe-polymorphic (`Type u` with `A`/`N.algebra B` in `Type u`, or
  at minimum `Type*`) in each listed declaration, matching `gns_construction`'s signature; this is
  a mechanical change since the proofs already obtain their witness from `gns_construction`.

### R13-8. Zero `**Restriction:**` markers exist anywhere in `Physicslib4/`
- severity: major
- category: lean-docstring
- location: repo-wide (`grep -rln "Restriction" Physicslib4/**/*.lean` → no matches)
- protected: no
- verdict: confirmed
- evidence: CLAUDE.md mandates recording every deliberate restriction on a docstring line starting
  `**Restriction:**`. A full-text grep for `Restriction` across all 111 non-`scratch_*` Lean files
  returns nothing at all. `CHANGELOG.md:45` confirms the convention was used at least once and then
  correctly removed when the general form was formalized ("carried a `**Restriction:**` note waiting
  on..."), so the mechanism works when exercised — but at present not a single deliberate narrowing
  in the library is recorded this way, even though several exist and are known (the already-reported
  missing restriction for the oriented identity component in HaagKastlerCurved/Concrete.lean, and the
  universe restriction on the GNS existence theorems in R13-7 below, which narrows `gns_construction`'s
  `Type u` conclusion to `Type` in over a dozen call sites without comment).
- proposed fix: treat R13-7 and the identity-component case as the first items of a sweep that adds
  `**Restriction:**` lines wherever a known narrower-than-intended statement is deliberately in place,
  so the convention actually tracks the project's technical debt as intended.
