## Findings

### R15-1. Missing `\uses` edge: `prpstn:integral-norm-bound` needs `lmm:lemma-1` directly
- severity: minor
- category: uses-tags
- location: blueprint/src/sections/sec10/spectral-theorems.tex:1305 (and `Physicslib4/Spectral/OperatorIntegral.lean:959`)
- protected: no
- verdict: confirmed
- evidence: the `\uses` list for `prpstn:integral-norm-bound` is
  `{def:adjoint-bounded, def:identity-operator, prpstn:hall-a.43, prpstn:integral-as-limit-of-simple, prpstn:integral-norm-bound-simple, prpstn:integral-of-indicator, thrm:complex-valued-simple-approximation-theorem, thrm:operator-valued-integration}`
  — it does not list `lmm:lemma-1`. But the Lean proof of `norm_integral_le` calls
  `opNorm_eq_sSup_inner` (the Lean name for `lmm:lemma-1`) directly: `rw [hT, opNorm_eq_sSup_inner]`
  (`OperatorIntegral.lean:959`), as part of an auxiliary "6×sup-norm" bound (`hSix`) that has no
  counterpart in the blueprint's own proof narrative for this proposition (the blueprint only
  reaches the sharp bound by reducing to simple functions and taking a limit).
- proposed fix: add `lmm:lemma-1` to the `\uses` list of `prpstn:integral-norm-bound`, or (better)
  add a sentence to the blueprint proof describing the polarization-based auxiliary bound that the
  Lean proof actually uses, since the Lean proof's structure diverges from the blueprint's at this
  point (the blueprint proves the bound by passing a limit through `integral-norm-bound-simple`
  alone; the Lean proof additionally needs a crude but uniform bound on `‖∫ (s_N - f) dμ‖` built
  from `lmm:lemma-1` via polarization, to control the approximation error before taking the limit).

### R15-2. Stray "proved by another prover" comment in `OperatorIntegral.lean`
- severity: minor
- category: lean-style
- location: `Physicslib4/Spectral/OperatorIntegral.lean:963-965`
- protected: no
- verdict: confirmed
- evidence:
  ```
  -- (II) the sharp bound for simple functions: ‖∫ s dμ‖ ≤ ‖s‖∞, cited as the
  -- black-box declaration `norm_integral_simple_le` (proved by another prover in
  -- the real file).
  ```
  `norm_integral_simple_le` is not in some other "real file": it is proved earlier in this very
  file (`OperatorIntegral.lean:621-830`). The comment is both factually wrong (there is no other
  file) and reads as leftover process narration about which agent/tool proved what, rather than
  documentation of the math — the kind of text the project's conventions ask to keep out of
  docstrings/comments.
- proposed fix: replace with a plain comment, e.g. "cited as the black-box declaration
  `norm_integral_simple_le`, proved above in this file."

### R15-3. `integral_bddMeasurable_mul` duplicates the proof of `tendstoUniformly_mul_of_bounded`
- severity: minor
- category: lean-style
- location: `Physicslib4/Spectral/OperatorIntegral.lean:1413-1482` (duplicate), cf. `:1589-1650+` (original)
- protected: no
- verdict: confirmed
- evidence: the docstring-adjacent comment admits the duplication outright:
  ```

  -- `tendstoUniformly_mul_of_bounded` (which lives below this declaration and so
  -- cannot be cited here), proved with the blueprint's ε/2-splitting.
  ```
  followed by a ~70-line reproof (`hdiag`) of the diagonal case of
  `tendstoUniformly_mul_of_bounded`, which is proved independently later in the same file

  mathematical difference, and is left unresolved rather than fixed by reordering.
- proposed fix: move `tendstoUniformly_mul_of_bounded` above `integral_bddMeasurable_mul` in the
  file and call it directly (specializing to the diagonal `r := r`, `s := s`) instead of
  reproving its diagonal case inline.

### R15-4. `\lean{}` tag for `prpstn:integral-of-indicator` covers only the first half of the statement
- severity: minor
- category: uses-tags
- location: blueprint/src/sections/sec10/spectral-theorems.tex:1259 vs. `Physicslib4/Spectral/OperatorIntegral.lean:466,521`
- protected: no
- verdict: confirmed
- evidence: the proposition reads "Then for all $E \in \Omega(X)$, $\int_X 1_E\,d\mu = \mu(E)$
  ... In particular, the integral of the constant function $1$ is the multiplicative identity
  $\mathbf{1}$." but `\lean{Physicslib4.Spectral.ProjectionValuedMeasure.integral_indicator}` names
  only the first clause; the "in particular" clause is a separate Lean theorem `integral_one`
  (`OperatorIntegral.lean:521`), not listed in the tag. The `integral_one` docstring itself notes
  it corresponds to "`prpstn:integral-of-indicator` (second part)", so the split is understood
  on the Lean side but not reflected in the blueprint's `\lean{}` tag.
- proposed fix: add `Physicslib4.Spectral.ProjectionValuedMeasure.integral_one` to the `\lean{}`
  tag of `prpstn:integral-of-indicator`.

### R15-5. Blueprint's Boundedness Theorem states an unneeded non-emptiness hypothesis
- severity: nit
- category: statement-correctness
- location: blueprint/src/sections/sec10/spectral-theorems.tex:2989-2994 vs. Mathlib
  `IsCompact.exists_bound_of_continuousOn`
- protected: no
- verdict: confirmed
- evidence: blueprint: "A continuous real-valued function on a non-empty compact set $C$ is
  bounded on $C$." The cited Mathlib lemma
  `IsCompact.exists_bound_of_continuousOn' : IsCompact s → ContinuousOn f s → ∃ C, ∀ x ∈ s, ‖f x‖ ≤ C`
  (`Mathlib/Analysis/Normed/Group/Bounded.lean:96`) carries no non-emptiness hypothesis — it is
  (vacuously) true for `s = ∅` as well. The blueprint statement is therefore narrower than what
  is actually proved, though harmlessly so (the stated case is the one used downstream).
- proposed fix: drop "non-empty" from the blueprint statement, or note that the hypothesis is
  retained only for readability/parallelism with Hall's text.
