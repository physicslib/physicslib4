## Findings

### R03-1. `\uses{}` on several capstone nodes is far broader than the node's own Lean proof
- severity: nit
- category: uses-tags
- location: `blueprint/src/sections/sec10/spectral-theorems.tex:3255` (`prpstn:hall-8.4`),
  also `:4836` (`thrm:hall-8.10`), `:5809` (`thrm:spectral-theorem-for-bounded-operators`)
- protected: no
- verdict: confirmed
- evidence: `prpstn:hall-8.4`'s Lean proof is exactly
  `theorem realCalculus_properties ... := ⟨realCalculus_mul hA, isSelfAdjoint_realCalculus hA,
  isPositive_realCalculus hA, norm_realCalculus hA, spectrum_realCalculus hA⟩`
  (`ContinuousCalculus.lean:336-344`), i.e. it only needs the four `prpstn:cfc-*` results.
  Its blueprint `\uses{}` list (line 3255) additionally cites
  `thrm:boundedness-theorem, thrm:composition-theorem, lmm:hall-prblm-7.4.8,
  thrm:operator-valued-integration, prpstn:hall-7.5, prpstn:hall-7.7,
  lmm:spectral-mapping-theorem, lmm:spectrum-is-compact-metric-measurable`, none of
  which the one-line Lean term touches directly. The same pattern recurs at the two
  other locations, which list dozens of labels transitively reachable from the proof
  rather than the direct dependencies.
- proposed fix: either trim these `\uses{}` lists to direct dependencies, or (if the
  project's convention is deliberately to list the full transitive closure for
  visualization) say so once in the blueprint's conventions, since as written it looks
  like `\uses{}` drift rather than a choice.

### R03-2. `@[nolint unusedArguments]` on `L0` has no inline rationale next to the attribute
- severity: nit
- category: lean-style
- location: `Physicslib4/Spectral/BorelClasses.lean:279-282`
- protected: no
- verdict: confirmed
- evidence:
  ```
  @[nolint unusedArguments]
  def L0 (X : Type*) [TopologicalSpace X] [MeasurableSpace X] : Set (Set X) :=
    {E | ∃ (f : ℕ → C(X, ℝ)) (C : ℝ), ...}
  ```
  The body only uses `[TopologicalSpace X]` (through `C(X, ℝ)`); `[MeasurableSpace X]`
  is carried for signature uniformity with the rest of the file but is genuinely
  unused here, which plausibly explains the lint suppression. The docstring above it
  (lines 264-277) explains the *mathematical* content and a different simplification
  (dropping the blueprint's explicit measurability conjunct) but does not mention the
  `nolint` or why `unusedArguments` fires.
- proposed fix: add a one-line comment next to the attribute, e.g. "`MeasurableSpace X`
  is unused here; kept for parity with the other definitions in this file."
