### R14-1. `mfderiv_apply_tangent_eq_zero` drops half the blueprint's conclusion
- severity: nit
- category: statement-correctness
- location: `blueprint/src/sections/sec10/spacetime.tex:476` (lmm:derivative-vanishes-along-path) and `Physicslib4/Spacetime/AlongPath.lean:47-59`
- protected: no
- verdict: confirmed
- evidence: Blueprint: "Then $f(\mu(s)) = 0$ and $df_{\mu(s)}\big(\dot\mu(s)\big) = 0$". Lean conclusion is only
  ```
  (show ℝ from mfderiv M.model 𝓘(ℝ, ℝ) f (μ.toFun s) (μ.tangent s)) = 0
  ```
  The theorem never states `f (μ.toFun s) = 0` as part of its conclusion (the proof uses the fact internally, at `h0.self_of_nhdsWithin hs` inside `h2`, but does not expose it).
- proposed fix: either state the conjunction (`f (μ.toFun s) = 0 ∧ mfderiv ... = 0`) to match the blueprint literally, or trim the blueprint's first clause (it is used only as a stepping stone, not elsewhere) and note in the docstring that it is proved en route but not asserted.

### R14-2. `IsGeodesic` is hardwired to `Spacetime`, not stated for a general pseudo-Riemannian manifold as the blueprint claims
- severity: minor
- category: blueprint-lean-mismatch
- location: `blueprint/src/sections/sec10/spacetime.tex:325` and `:538` (def:geodesic) vs `Physicslib4/Spacetime/Causality.lean:57,80-84`
- protected: no
- verdict: confirmed
- evidence: Blueprint lead-in (line 325): "The following declarations make 'geodesic' precise. ... They are stated for a general pseudo-Riemannian manifold, of which every spacetime is an instance ... No chart appears in any definition." def:geodesic itself (line 538): "Let $(M,g)$ be a pseudo-Riemannian manifold (for instance a spacetime) with Levi-Civita connection $\nabla$ ... A smooth path $\mu:\Sigma\to M$ is a geodesic if ...". This generality is real for `def:pseudo-riemannian-metric` through `thrm:levi-civita-exists-unique` (all stated over arbitrary `{E,H,I,M}` in `LeviCivita.lean`/`Basic.lean`). But `IsGeodesic` is declared as
  ```
  variable (M : Spacetime)
  def IsGeodesic (μ : M.SmoothPath) : Prop :=
    ∀ s ∈ interior μ.parameterSpace, ∀ X : Π x : M.Carrier, TangentSpace M.model x,
      ContMDiff M.model (M.model.prod 𝓘(ℝ, SpacetimeModel)) ∞ (T% X) →
      (∀ᶠ t in 𝓝 s, X (μ.toFun t) = μ.tangent t) →
      M.toPseudoRiemannianMetric.leviCivita X (μ.toFun s) (X (μ.toFun s)) = 0
  ```
  i.e. it takes a `Spacetime`, not an arbitrary pseudo-Riemannian manifold `(M,g)` with its own path type and metric `g`; there is no general-manifold `IsGeodesic`. This is because `SmoothPath` (`def:paths`) is itself only defined for `Spacetime` — so the restriction is inherited, not a bug in this file, but the blueprint's "stated for a general pseudo-Riemannian manifold... (for instance a spacetime)" phrasing, repeated specifically for def:geodesic, overclaims generality that the Lean code (and, transitively, `def:paths`) does not have, and nothing in the blueprint or a `**Restriction:**` docstring line flags this gap for the geodesic definition.
- proposed fix: narrow the prose for def:geodesic (and the line-325 lead-in, as far as it covers def:geodesic) to say the path/manifold here is a spacetime specifically, since `\Sigma \to M` already presupposes a `Spacetime`-typed path; or, if a general-manifold geodesic notion is intended later, add a `**Restriction:**` line to `IsGeodesic`'s docstring naming what it is waiting on (a general `Path`/`SmoothPath` for arbitrary pseudo-Riemannian manifolds).

### R14-3. Inconsistent/unusual LaTeX markup for subscripted Lean/Mathlib identifiers
- severity: nit
- category: prose
- location: `blueprint/src/sections/sec10/spacetime.tex:429` and `:442`
- protected: no
- verdict: confirmed
- evidence: `\texttt{tensorialAt\_leviCivitaAuxInner\ensuremath{_1}}`, `\texttt{tensorialAt\_leviCivitaAuxInner\ensuremath{_3}}` (line 429), `\texttt{TensorialAt.mkHom\ensuremath{_2}}` (line 424/442 area). Elsewhere identifiers with unicode digit subscripts (e.g. `koszulAux`, `IsLeviCivitaFor.koszul`) are typeset directly in `\texttt{}` without `\ensuremath{}`. Mixing math-mode subscripts inside `\texttt{}` can render in a different (italic/math) font than the surrounding monospace text, inconsistent with the rest of the document.
- proposed fix: typeset these identifiers the same way as all the others (plain `\texttt{...₁...}` with the actual unicode subscript character, or an escaped underscore `\_1` consistently), rather than switching to `\ensuremath{}` for just these two lemma names.
