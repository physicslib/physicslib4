blueprint node, and is unused anywhere in the repository.**

- Location: `Physicslib4/AQFT/HaagKastler/CovariantState.lean:91–131`.
- Problem: this is a substantial, carefully-documented definition (fiberwise

  `haag-kastler-axioms.tex` — confirmed by `grep -n "IsWeaklyContinuousAction"

  It is also not referenced by any other Lean declaration
  (`grep -rn "IsWeaklyContinuousAction" Physicslib4/` returns only its own

  (`isPure_precomp_action_iff`, also still unlinked): a real, non-trivial
  Lean-only convenience definition that the blueprint's declaration graph does
  not track. It is not a faithfulness defect — nothing depends on it, so it
  cannot mislead a downstream theorem — but it means two now-existing
  declarations (this one and N2's) sit outside the audited graph.
- Classification: missing `\uses`/node coverage, not a mismatch.
- Suggested fix (propose only): either add a short blueprint node for

  intentionally a Lean-only scaffold not yet promoted to a blueprint node.

### Observation (not a defect)

**P1 — `HaagKastlerNet.IsVacuumState`'s abstract `ftl` parameter is vacuously
satisfiable, by design, and the one place this matters is handled correctly.**

`IsVacuumState N ftl ω` conjoins invariance with `∀ γ, IsOneParameterSubgroup γ
→ ftl γ → IsPositiveEnergy (...)`. Since `ftl : (ℝ → InhomogeneousLorentzGroup)
→ Prop` is a free parameter, choosing e.g. `ftl := fun _ => False` makes the
second conjunct vacuously true for *any* invariant state, so the parameterized
form by itself proves nothing about the spectrum condition. This is exactly
the "predicate satisfiable by trivial data" shape the task asked me to look
for, and I traced every consumer to make sure it isn't silently exploited:
- The blueprint text itself flags `ftl` as "a parameter, to be instantiated
  once the translation subgroup ... and its causal structure are wired in"
  (`def:vacuum-state`, tex lines 1794–1801), and supplies exactly one instance,
  `IsFutureTimelikeTranslation` (a real, non-vacuous existential predicate over
  the forward Minkowski cone), via `IsVacuumStateConcrete`
  (`def:vacuum-state-concrete`).
- The two theorems that consume `N.IsVacuumState ftl ω`
  (`IsVacuumState.invariant`, `IsVacuumState.exists_gns_irreducible_covariant`)
  use only the invariance conjunct (`h.1`), never the positive-energy
  conjunct, exactly as documented ("no-Stone consequences", tex lines
  1803–1815) — so no theorem is claiming spectrum-condition content it hasn't
  earned via a vacuous `ftl`.
- `IsVacuumStateConcrete` fixes `ftl` to the honest predicate, so the "final"
  object a consumer would actually use is not exploitable this way.
No action needed; recorded because it is exactly the audit pattern the task
asked me to hunt for and I wanted the trace to be visible rather than silently
passed over.
