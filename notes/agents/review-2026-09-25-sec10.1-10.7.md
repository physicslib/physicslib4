### Low

**L1. `def:general-covariance-in-curved-spacetime`'s `\uses{}` list does not
directly cite `def:haag-kastler-net-in-curved-spacetime`, even though the
node's own statement (`\mathrm{HaagKastlerNet}(L.\mathtt{toAbstractIdentityComponent})`)
names it and the commit under review (`bc0d8c5`) changed exactly which
`HaagKastlerNet`-producing bridge is used.**

The current list is
`\uses{def:net-equivalence-in-curved-spacetime, def:pullback-metric,
def:lorentzian-spacetime, thrm:pullback-is-lorentzian-spacetime,
lmm:pullback-preserves-future-orientation,
lmm:cross-metric-isometry-preserves-basis-sets, def:cross-metric-isometry}`
(`general-covariance-in-curved-spacetime.tex:45`). `def:haag-kastler-net-in-curved-spacetime`
is reachable transitively (`def:net-equivalence-in-curved-spacetime` already
`\uses`s it), so this is not a broken dependency graph, and it is not a
blocking issue. But given that this session's fix was precisely about which
`HaagKastlerNet` bridge (`toAbstract` vs. `toAbstractIdentityComponent`) is
plugged in here, and the node's remarks discuss Axiom 5
(`def:isometric-covariance-in-curved-spacetime`) by name (`\ref`, not `\uses`),
a direct edge to `def:haag-kastler-net-in-curved-spacetime` (and arguably to
`def:isometric-covariance-in-curved-spacetime`) would make the dependency
graph self-documenting for exactly the point this fix addressed.

*Suggested fix*: add `def:haag-kastler-net-in-curved-spacetime` (and optionally
`def:isometric-covariance-in-curved-spacetime`) to this node's `\uses{}` list.
No Lean change needed.
